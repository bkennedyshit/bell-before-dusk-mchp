# 0.2.2 UI asset and verification

Generated with the built-in image-generation tool, not the CLI. Original
commercial UI references supplied by the user were used for material/hierarchy
direction only; their images, logos and layouts are not bundled in the game.

Final asset: `assets/ui/washi-panel-v1.png`. Opaque cream washi, walnut rim and
restrained brass corners. Original output retained at the tool's generated-image
location. No existing asset was overwritten. All labels, actions and route-map
states remain code-rendered; the generated paper is a cached nine-slice background.

## Final prompt

Use case: stylized-concept. Asset type: production 9-slice UI background for a portrait Japanese pixel-art samurai adventure game. Generate ONE square panel filling the canvas edge-to-edge, viewed straight on, perfectly rectangular with straight parallel edges. A thin dark walnut/lacquered wood rim, restrained aged brass corner bindings, a very fine inner ink border. Center is warm ivory handmade washi paper, nearly uniform quiet pale cream, subtle fine fibers only, no large stains. Outer border occupies only 5% of the width on every edge. Keep the entire central 85% completely empty and evenly light for dark text, maps and interactive buttons to be drawn in code later. Crisp hand-painted pixel-art craft, grounded Edo Japan materials; no fantasy filigree, no dragons, no bells, no bulky 3D shading. No writing, no lettering, no symbols, no watermark, no buttons, no scene, no extra objects. Opaque image, no transparency, square 1024x1024.

## Implementation

- Journal, route map, dialogue, trail selection and shops use quiet parchment
  instead of a noisy stretched teal texture. Lacquer action rows and a quieter
  campaign HUD give the action and current lead distinct visual priorities.
- Running-body shadows stay at the actor anchor, not the current leading foot.
  Expanded bandits have an actual 50px silhouette height and a 10px shadow radius.
- Road plaques fade against the hero's visible body footprint, including the
  Post Town overlay which draws after the character.
- Sprite measurement metadata is generated read-only by
  `tools/measure-run-sprites.py`. The artwork is not modified. Runtime masks use
  those premeasured row spans instead of flood-filling three large atlases during
  play. The existing runtime fallback remains if metadata is unavailable.
- Low-FPS game time advances in <=1/60-second physics substeps, capped to 100ms
  after a long stall. Rendering still happens once per animation frame.
- Platform terrain tap walks horizontally; character tap slashes; double terrain
  tap hops and triple terrain tap makes a high jump. The 260ms recognition window
  distinguishes double/triple taps. Joystick and hold/release buttons remain.

Human playtesting is still pending; use `design/HUMAN-PLAYTEST.md`. Automated
checks do not establish comfort, immersion, commercial readiness or low-end
physical-phone performance.
